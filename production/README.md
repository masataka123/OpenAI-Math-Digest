新しいカタログに034・033の過去の担当範囲、公開許可、固定の図数、略号をコピーしない。現在のユーザー指示を優先し、変更した共通仕様は版と変更点を残す。進行中のカタログには採用版を記録し、共通仕様を更新しただけで既存記事を一括書き換えない。

このセットは制作指示と雛形である。引用の整合性は自動検査するが、全項目の自動検査や数学的な妥当性の認定をするものではない。既存の検査で扱えない項目は担当が確認して記録する。

## 論文数に応じた運用

| 収録状況 | 担当 | カタログページ |
|---|---|---|
| 1本 | Astra執筆担当が記事と案内を担当し、別のAstra担当が内容点検。Sol本部が進行・組込み | 短い概要、1本の記事への入口、日英PDF、原典・確認範囲。論文間の総括図や選択UIは省く |
| 少数 | Astra担当が順次執筆、または負荷に応じて分担。Sol本部が統合 | 公式順一覧と必要な接続だけ。無関係な論文を一つの証明経路にまとめない |
| 多数・長文 | 原稿の長さ、方法、直接入力、既存記事の有無を見て可変人数に分担 | 公式順一覧、内容に応じた複数の経路、結果単位の接続 |

- 担当人数、カタログの「流れ」の数、図数はそれぞれ別に決める。3担当・3分類・3図を標準値にしない。
- 1本でも記事の主定理・証明・引用の品質と日英PDFは省略しない。長く難しい原稿も、初稿は核心に絞って最大60分で区切る。
- 1本の場合のPDFは短いカタログ案内＋記事1本の2章。記事の証明図をカタログにも複製する必要はない。
- 1本でも他カタログ・外部文献への入力／利用関係はあり得る。重要な接続だけ本文や短い一覧で案内し、同じカタログ内の論文間依存と混同しない。
- 複数本でも確認できた接続がなければ関係図を作らない。「未調査・未記録」と「調べた範囲で直接利用を確認できなかった」を区別する。

## 役割と変更範囲

| 担当 | モデル／思考量 | 成果物・責任 | 通常の変更範囲 |
|---|---|---|---|
| 記事・数学的案内の執筆 | `gpt-6-astra` / `high` | 原典読解、日英記事と案内、図の論理、出典・時間・未確認記録 | 割り当てられた `drafts/catalog-NNN/` |
| 内容点検（執筆者とは別担当） | `gpt-6-astra` / `high` | 原典と主張・帰着・直接入力・日英・カタログ接続の照合 | 担当の内容点検記録。修正は執筆担当へ返す |
| カタログ本部 | `gpt-6.1-sol` / `xhigh` | 台帳、分担、受領・形式統一、Astraの内容点検・修正の取りまとめ、引継ぎ | `coordination/catalog-NNN/`、当該カタログの組込み。並行中の記事は担当へ返す |
| サイト本部 | `gpt-6.1-sol` / `xhigh` | 共通表示、サイト登録、図の機械処理、PDF生成、全体検査、公開反映 | `src/`、`public/`、`scripts/`、共通文書・設定、統合後の全体 |

Sol本部はカタログ本部とサイト本部を兼ねてよい。1本でも数学の執筆・内容点検をSolが兼任しない。仮定・結論・数式・引用の適用・数学的な日英対応の変更はAstraへ返す。実際のモデル・思考量と担当をMODEL_PROVENANCEへ記録する。PDFはサイト本部が責任を持ち、未生成なら引継ぎに「PDF待ち」を残す。

共通ファイル、とくに `site.mjs` と `pdf-editions.json` の書き込みはサイト本部で順番に行う。記事本文は担当フォルダを分けて並行作業できる。共有作業場のブランチを切り替えたり、他担当の未コミット変更を消したりしない。Git競合では双方の差分を照合し、ours/theirsで一括選択しない。

この文書自体は新しいチャット作成・他チャットへの送信・公開の依頼ではない。それらは現在のユーザーによる指示の範囲で行う。すでに依頼された操作について重ねて確認を求める必要はない。

## 標準の3段階と停止（1.4補足・2026-10-12）

制作開始後の途中停止は原則2回。下記の工程番号と段階番号を混同しない。棚卸し・構成確認は第1段階の冒頭に含められ、準備だけの報告をユーザーが求めた場合のみ別に区切る。

1. **第1段階：記事制作・内容点検・カタログ案内**。Astraが日英記事・図の数学的内容・出典・接続・案内を制作し、執筆者以外のAstraが原典と照合する。Sol本部が受領・形式統一と内容修正の引渡しを行う。担当人数は本数・負荷に応じて可変。成果物・未確認事項・引継ぎを報告して停止。サイト組込み・PDF・公開へ自動的に進まない。
2. **第2段階：サイト組込み・日英PDF・公開前検査**。再開指示後、サイト本部（兼任可）が組込みとPDF生成、本文・図・PDFの一致、引用・数式・リンク・画面・紙面を確認する。欠け・重なり・読めない箇所・内容不一致は修正し、必要な検査を満たしたら軽微な余白や改ページの調整を追加し続けない。公開準備の結果を報告して停止し、commit・pushによる公開はまだ行わない。
3. **第3段階：公開・反映確認**。公開指示後、対象変更をcommit・pushし、Actionsと公開ページ・図・日英PDFの反映を確認して完了報告。

各停止時には現在の段階、作業場所・ブランチ、成果物、完了事項、検査結果、未確認事項、残作業、再開手順を引継ぎ記録へ残す。初稿引渡し・内容編集済み・公開準備完了・公開確認済みを区別する。未完成や必須検査の失敗が残る状態を完了と報告しない。

現在のユーザーが「公開まで一括で進める」等を指示している場合は停止を省く。明示された途中停止があれば尊重する。この標準を理由に承認済みの同じ範囲を再確認しない。過去の別カタログの公開許可は引き継がず、進行中の仕事の停止条件も自動変更しない。

## 制作の順序

1. **棚卸し**：Git状態、公式番号・分野・英語表記・掲載順、原稿版・ページ・ハッシュ、既存記事の有無を確認。[RECORDS.md](RECORDS.md) に沿って台帳を作る。同じ論文が既存カタログにあれば同じpaper IDと記事を再利用し、原稿版の違いを記録する。
2. **構成と担当**：単論文／複数論文の構成、担当、変更範囲、PDF担当、公開範囲を `coordination/catalog-NNN/README.md` に記録。[START_CATALOG.md](START_CATALOG.md) と [WORKER_TEMPLATE.md](WORKER_TEMPLATE.md) を使う。
3. **記事初稿**：1本ごとに読解・執筆・図・確認を合わせ最大60分。開始・締切・終了を記録。下限なし。未完成なら未完成と明記し、自動延長しない。担当に次の記事があれば本部の確認待ちで止めず進む。
4. **受領ごとの編集**：Astraが日英の数学的対応、定理・証明・根拠・未確認を点検し、Sol本部は形式と修正の完了を確認する。全記事が揃うまで不統一を放置しない。修正一覧は記事ごとにまとめ、編集時間は初稿と別に記録する。
5. **カタログ案内**：Astraが記事の用語と結果を照合してから、確認できた接続を総括にする。FORMAT_CONTRACT.md第6節により主要な接続をまとめた図を検討する。全体像は図、細部は表を基本とし、一対一の辺の多さだけで図を省略しない。図が理解を助けない場合は省略する。単論文では短い入口にする。原典の供給結果→利用箇所→目的→必要な仮定を記録する。
6. **サイト組込みとPDF**：サイト本部が共通の文字・図・日英切替・ナビゲーションを使って登録。日英PDFを生成し、カタログ冒頭にリンクを配置する。
7. **検査と公開**：[RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) に証拠を記録。公開が依頼範囲なら反映し、Actionsと公開URLを確認する。公開が範囲外なら公開前までの成果物と残作業を明示する。

## 第2段階の共通処理と引継ぎ（1.4運用補足・2026-10-19）

サイト登録と対象図の配置を終えたら、1カタログずつ `npm run catalog:prepare -- --catalog NNN` を使う。第1段階で生成・確認した図は原本とハッシュを照合して使い、変更がない限り再コンパイルしない。
引用・テスト・ビルド・対象PDF照合・必要な日英PDF生成・内部リンク・日英PC/375px画面検査を共通処理で実行する。
カタログ専用のPDF生成・リンク補完・画面検査スクリプトを新たに複製しない。仕様外の必要な検査だけを補足する。
詳細は[実行手順](../scripts/pdf/README.md)と[画面検査](../scripts/browser/README.md)を参照。

各実行の `tmp/catalog-preparation/NNN/<実行日時-PID>/HANDOFF.md` に時間・成否・Git状態・PDF版情報・画面記録・実行環境・再実行方法がまとまる。
担当者は画像一覧・日英PDFを確認し、同じ実行フォルダの `REVIEW_ENTRY.md` をひな形に `coordination/catalog-NNN/PREPARATION_REVIEW.md` へ目視結果・判断・残作業を追記する。数値・ハッシュ・ログはHANDOFF/reportへの参照で済ませ、同じ機械記録を複数文書へ転記しない。
この担当者用ファイルは初回だけ自動作成され、再実行で上書きされない。実行ごとのHANDOFFも別フォルダに残る。
第1段階の `SITE_HQ_HANDOFF.md` は内容引継ぎとして維持し、自動記録で置き換えない。
機械検査の成功を目視・数学的内容の承認にせず、第2段階の結果を報告して標準どおり停止する。一括公開の現在の指示は優先する。
検査後に変更した対象は再検査する。同一版の目視証拠を参照する場合はファイルの同一性・元の確認範囲を確かめ、参照理由を明記する。長期保存や別の作業場への引継ぎでは、Git対象外の実行フォルダと必要な証拠を保存し、その場所を記録する。
別チェックアウトでは共通コマンドを含む更新を取り込んでから開始する。未導入なら旧手順を独自に再実装せず、更新状況を報告する。

## 完了の区別

- **初稿引渡し**：担当成果物と未確認・未完成を渡した状態。時間上限で区切っただけでは記事完成ではない。
- **内容編集済み**：日英記事・図・総括・出典の必要な編集を終えた状態。PDF・公開は別に記録する。
- **公開準備完了**：必須成果物、サイト組込み、日英PDF、必要な検査が揃った状態。
- **公開確認済み**：依頼された公開を実施し、公開サイトでも反映を確認した状態。

数学的確認は別軸である。入力定理の記述と使用箇所の照合、証明の一部の読解、全証明の独立検証を区別する。保留の接続は断定しない。形式検査やビルド成功を数学的正しさの認定にしない。

## 既存実装を使う範囲

- 記事：`src/lib/render-draft.mjs` と `article-structure.mjs`、共通CSS・図拡大部品を使う。引用だけの独立段落が出典表示になる。[雛形](ARTICLE_TEMPLATE.md) を参照。
- カタログ：新規には `CatalogMarkdownOverview.astro` を使い、単論文の省略条件とカタログ別データを確認する。033・034は既存の表示部品を維持しているため、引用・出典欄は公開前に比較する。033専用の `CatalogDraftOverview.astro` を番号だけ置換して使わない。
- PDF：登録済みカタログごとの生成は実装済み。[PDF手順](../scripts/pdf/README.md) を使い、別の冊子生成系を作らない。
- 図：既存の `diagrams` / `diagrams:catalog` はすべての新規原稿を自動検出するものではない。担当は自分の図だけを生成する手順を記録し、無関係な図を上書きしない。
