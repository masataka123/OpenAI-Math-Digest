# 新しいカタログ本部への開始プロンプト

`NNN` を3桁の公式カタログ番号に置き換え、対象リポジトリを開いた別窓口に貼り付ける。通常は「第1段階」から始め、必要な棚卸しもその冒頭で行う。準備だけを先に相談したい場合は任意の「準備」プロンプトを使う。制作開始後の標準停止は第1・第2段階の末尾の2回。論文数や担当人数は先に固定しない。

本部チャットは **Sol 6.1・極高** を選んで開始する。数学の執筆・別担当の内容点検には **Astra 6・高** を明示指定する。[MODEL_ROLES.md](MODEL_ROLES.md)を適用し、プロンプトの文字列だけで本部の設定が変わったとは扱わない。

## 途中停止を省いて一括で依頼する場合

ユーザーが一括進行を望む場合のみ、第1段階の依頼へ次を添える。現在の依頼で既に同じ範囲の公開が承認されていれば、重ねて確認しない。

```text
今回は第1〜第3段階を途中停止せず、サイト本部を兼任して公開・反映確認まで一括で進めてください。各段階の成果物と検査記録は残し、必須検査を省略しないでください。
```


## 制作セット1.4の必須形式

[FORMAT_CONTRACT.md](FORMAT_CONTRACT.md)を適用する。共通の公式順表、図前の文献一覧、本稿内／外部の引用区別、証明対象・原典読書案内の4項目を埋める。各記事の受領時に見本と比較し、全記事完成まで待たない。`npm test`と`npm run check:citations`に加え、034の表・Schnell・033 Orbifold Iitakaと実画面を比較し、日英PC／375pxと日英PDFの証拠を記録する。

## 主張と証明の対応（1.3必須）

- 主要結果の全結論に証明概略と説明先を対応させる。必要な全体図を詳細節より前へ置く。
- 独立して証明を解説する命題は、図より前に原典の仮定・結論・番号・ページを記す。番号だけの「証明対象」で代用しない。
- 主張欄、mainResults、statements、conclusionCoverageをFORMAT_CONTRACT.mdに従い用意し、日英を揃える。
- Astraの内容点検担当が原典の仮定・量化と主定理への接続を照合し、Sol本部がその記録を受領する。各主張の原典ページ、各結論の説明先、確認済み／未確認を残す。
- 自動検査に加え、Schnell・Orbifold Iitakaとの主張欄→図→直後の説明の画面比較、日英PDFへの反映を確認する。

## 新規引用の表示（1.4）

新規レジストリは `citationStyle: "author-key"` を指定する。本文・図は `[FL13, Theorem 1.1, p. 2]` 等の著者由来キーで引用し、図前の文献一覧で著者・正式タイトル・参照版を定義する。結果の使用内容は説明する。042・051を含む既存記事・図・PDFは遡及変更しない。詳細はCITATIONS.mdを参照。
