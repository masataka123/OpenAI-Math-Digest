# 制作のモデル分担と再利用

制作セット1.4の運用補足（2026-10-20）。今後の新規制作に適用する。記事の形式・数学的な確認範囲・3段階の停止条件は維持する。

## 担当と指定

| 担当 | モデル／思考量 | 作業 |
|---|---|---|
| 全体本部・カタログ本部・サイト本部 | `gpt-6.1-sol` / `xhigh`（極高） | 進行、原典取得、書誌台帳、担当への引渡し、形式検査、組込み、生成処理、表示・紙面確認、公開、記録 |
| 数学の執筆 | `gpt-6-astra` / `high`（高） | 原典読解、日英記事、主張・証明戦略・直接入力、図の数学的内容、日英カタログ案内・接続・構成の数学的判断、内容修正 |
| 数学の内容点検 | `gpt-6-astra` / `high`（高）、執筆者とは別担当 | 主張の仮定・量化・結論、証明の帰着・適用条件、日英対応、カタログの接続を原典と照合 |
| 共通スクリプト | モデルなし | 引用生成、TeX/SVG変換、PDF生成、整合性・表示検査、工程時間と結果の記録 |

単論文でもSol本部は数学の執筆を兼任しない。Astra執筆担当1名と別のAstra点検担当を用い、単論文の案内は執筆担当が兼ねる。複数論文では負荷に応じて担当範囲を決め、点検担当は複数記事をまとめて受け持てる。点検のために全文をもう一度執筆しない。

本部チャットはユーザーがSol 6.1・極高を選ぶ。文章による指定だけで現在のチャットの設定が変更されたとは扱わない。サブエージェントを使う依頼では生成時に `model: "gpt-6-astra"`, `reasoning_effort: "high"` を明示し、必要な原典台帳・指示・担当範囲・保存先を渡す。本部のモデル・思考量を継承するだけで済ませない。指定できなければその役割を別モデルで代行せず報告する。

実際の指定方法・担当・モデル・思考量を [RECORDS.md](RECORDS.md) のMODEL_PROVENANCEへ残す。希望値と実際に指定できた値を区別し、取得できない実行情報を推測で埋めない。この文書の整備だけでは新しいチャットや担当の起動を依頼していない。

## Sol本部が変更できる範囲

- 検査済み原稿の登録、公式順・導線・アンカーの維持、共通部品への組込み。
- 記録に従う引用の同期と図のコンパイル・コピー、文字の重なり・余白・改ページの修正。
- 機械検査、PC/スマートフォン表示とPDF紙面の確認、不具合修正、公開と反映確認。

仮定・結論・数式・図の矢印の意味・引用する結果や適用箇所・日英の数学的意味を変える必要があれば、修正内容をAstraへ返す。接続の採否や分類の妥当性もAstraが判断し、本部はその結果を採用する。Solの読み直しを数学的内容点検の代わりにしない。内容修正後はAstraが影響する主張・接続を確認し、変更された成果物だけを再生成・再点検する。

既存Sol制作の数学的原稿・図・解釈・点検結果を新規制作の根拠として使わない従来の指定は維持する。公式原典、共通表示、指定見本、および今回Astraが制作・点検した同一版の成果物は再利用できる。Solが機械処理を担当したことだけを理由に、その成果物を破棄・再執筆しない。既存公開記事の自動改訂は行わない。

## 二重作業を避ける手順

1. **受領**：原稿・sources・内容点検記録・citations・図の生成記録を参照して内容確定版を特定する。本部が原典読解と記事執筆を最初から繰り返さない。
2. **図**：第1段階のTeX/SVGを配置し、既存の `check:citations` が原本・生成物のハッシュと公開コピーを照合する。同期結果・原本・生成条件が変わっていなければ再コンパイルしない。不一致なら原因を直し、影響する図を再生成する。生成せずハッシュだけ更新しない。
3. **PDF**：`catalog:prepare` が現在の本文・図・組版とファイルハッシュを照合する。一致した版は再利用する。通常は `--regenerate-pdf` を付けず、必要な更新だけ生成する。
4. **確認**：新規・変更された画面・図・紙面は担当が確認する。同じ版の目視記録を参照する場合は、現在のファイルとの同一性と元の確認範囲を確かめて記録する。新版、未確認範囲、共通表示・組版の変更へ旧確認を自動承継しない。実行ごとの共通検査と公開後の反映確認は維持する。
5. **記録**：機械の数値・ハッシュ・工程ログは自動HANDOFF/reportを唯一の参照先とする。担当者は `REVIEW_ENTRY.md` のひな形に目視結果・判断・未確認事項・次の操作を記入し、PREPARATION_REVIEWへ追記する。複数の報告書に同じ表やログを書き直さない。
6. **再開・公開**：第2段階の確認済みPDFを公開のためだけに作り直さない。現在の差分と対象版を確認し、変更の影響範囲を再検査する。Actionsと公開リソースの反映を確認する。新しい計測・検査基盤をカタログごとに作らない。

## 環境と所要時間

初回に使えたNode・Python・Chromeと設定の場所を記録する。共通処理は実行環境とNode直起動の再実行コマンドをHANDOFF/reportへ残す。次回は記録のパスの存在を確認して使い、見つからない場合や環境エラー時だけ再調査する。npmがない環境では利用可能なNodeで `scripts/prepare-catalog.mjs --catalog NNN` を直接実行できる。端末固有の絶対パスを制作プロンプトへ固定しない。必要な実行許可は利用環境の手順に従い、設定ファイルで権限を回避しない。

数学の初稿時間はstatus.md、自動処理はreport.json、その他の本部作業はPREPARATION_REVIEWの概数で分ける。公開時のActions待ちも区別する。計測のためだけに詳細な時系列報告を増やさず、モデル分担による速度・利用量の改善を未計測のまま断定しない。
