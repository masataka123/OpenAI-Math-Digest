# カタログの共通画面検査

第2段階の `npm run catalog:prepare -- --catalog NNN` に含まれます。
登録済みカタログと `paperIds` から対象を取得するため、カタログ専用の検査スクリプトや
記事名・図枚数の手入力は不要です。記事やPDFは編集せず、ビルド済みサイトを検査します。

## 実行

```sh
# 通常はビルド・PDF・リンク検査とまとめて実行
npm run catalog:prepare -- --catalog NNN

# 画面だけ再確認する場合（先に npm run build）
npm run check:browser -- --catalog NNN --references
```

Node依存は `npm ci`、ブラウザはインストール済みGoogle Chromeを使います。
Chromeの場所が通常と違う場合は `PDF_BROWSER_PATH` を指定します。
`tmp/pdf-runtime.json` の同名設定も利用できます。Python・PDF生成環境は単独の画面検査には不要です。
実際のサイトと同じMathJax CDNへ接続するためネット接続が必要です。
CDNの読み込み失敗やタイムアウトは成功扱いにせず、記録を残して失敗します。

`--dist DIR` で検査するビルド、`--output DIR` で記録先を変更できます。
既定の記録先は `tmp/browser-checks/NNN/<実行日時-PID>/`。
`catalog:prepare` からは各回のログフォルダ内の `browser/` にまとめます。
一時サーバーはループバックの空きポートを使い、終了時に閉じます。

## 自動で調べること

- 対象カタログと全登録記事の日本語・英語。画面幅1280pxと375px、高さ900px。
- ページ全体の横はみ出し、数式エラー、画像読み込み失敗、JavaScript・HTTPエラー。
- 図・数式・表の横長部分を実際にスクロールできるか。スクロールで読める表や数式は許容。
- カタログ一覧の4列、公式登録順、記事へのリンク、対応言語のPDFリンク。
- 全証明図の拡大・ズーム・画面幅への調整・閉じる操作、拡大後の引用リンクの保持。
- 下までスクロールした後の言語切替の可視性、切替先の言語と共通アンカー。
- 検査前後のHTMLハッシュ。途中で再ビルドされたページは失敗扱い。

全ページの長いスクリーンショットと、各表示条件で最初の証明図を拡大した画像を保存します。
`--references` は034カタログ・Schnell・Orbifold Iitakaの日英PC幅の比較画像も加えます。
対象と重複する見本は再取得しません。`catalog:prepare` ではこの指定を常に付けます。

`index.html` は画像一覧、`report.json` は成否・URL経路・画面幅・検出内容・検査時刻・
Chrome版・HTMLハッシュの記録です。失敗時は終了コード1となり、準備工程も停止します。
原因を直した後、対象を指定して再実行してください。過去の画像を合格の根拠に再利用しません。

## 人が確認する範囲

自動合格は公開許可や数学的内容の承認ではありません。画像一覧を開き、見本と比較して
主張欄・引用・証明対象・原典案内、図の文字の重なりや読みやすさを確認します。
図の内容の正しさ、ページ間の数学的な日英一致、PDF紙面は別途確認してください。
375pxはChromeでの狭幅検査です。実機Safariでの動作確認を意味しません。
外部引用先への到達確認はこの処理には含めません。

公開処理やGitHub Actionsにはブラウザ検査を追加していません。
第2段階で画像と結果を保存し、第3段階の高速リンク検査は維持します。

## 検査処理を変更したとき

```sh
npm test
npm run test:browser
```

後者は実際のChromeで、正常な横スクロールを許容し、はみ出し・切れた数式・画像失敗・
壊れた図操作や非表示の言語切替を検出できるか確認します。
故意の不良ページによる `FAIL` 出力が出ますが、テスト自身の合否は末尾を参照してください。
カタログ専用スクリプトは履歴として残りますが、新規制作はこの共通処理を使います。
